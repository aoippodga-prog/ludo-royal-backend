# خادم تجريبي للعبة لودو رويال

هذا مشروع Backend تجريبي أُعدّ بناءً على تحليل ملف APK المرفق. اكتُشفت فيه واجهة tRPC تستخدم المسار `/api/trpc` وإجراءات باسم:
`ludo.create`, `ludo.join`, `ludo.room`, `ludo.start`, `ludo.rematch`, `ludo.roll`, `ludo.move`.

## تنبيه مهم قبل النشر
- هذا خادم أولي مبني من واجهة العميل الظاهرة داخل APK، وليس الخادم الأصلي الذي أنشأه مطوّر اللعبة.
- لم يتم اختبار هذا الخادم مع التطبيق على هاتف فعلي. يجب تجربة الغرف والحركات بعد النشر، وقد نحتاج إلى تعديل شكل بيانات الحالة ليتطابق تمامًا مع ما يتوقعه محرك الرسم في APK.
- الغرف مخزنة في ذاكرة العملية فقط؛ عند إعادة تشغيل الخدمة أو نومها قد تضيع الغرف. لا تستخدمه كخادم إنتاجي.
- منطق لودو المضمّن مبسط، وقد يحتاج مطابقة أدق مع قواعد/تمثيل اللعبة الأصلية.

## النشر المجاني على Render
1. فك ضغط الأرشيف.
2. ارفع مجلد المشروع إلى مستودع GitHub جديد.
3. افتح Render وأنشئ **New Web Service** ثم اربط مستودع GitHub.
4. الإعدادات:
   - Runtime: Node
   - Build Command: `npm install`
   - Start Command: `npm start`
   - Health Check Path: `/health`
5. انتظر نجاح النشر. سيكون العنوان شبيهًا بـ `https://ludo-royal-backend.onrender.com`، لكن اسم النطاق الفعلي تحدده Render.

## وضع العنوان داخل اللعبة
في إعدادات الخادم داخل التطبيق، أدخل **العنوان الفعلي الذي يعطيك Render** فقط، مثل:
`https://YOUR-SERVICE-NAME.onrender.com`
لا تضف `/api/trpc`؛ التطبيق يضيف هذا المسار تلقائيًا.

## اختبار سريع
بعد النشر، افتح:
- `https://YOUR-SERVICE-NAME.onrender.com/`
- `https://YOUR-SERVICE-NAME.onrender.com/health`

ينبغي أن يعرض الأول معلومات API والثاني `{"ok":true}`.

## حدود النسخة المجانية
قد يتوقف التطبيق مؤقتًا عند عدم الاستخدام، وقد تُحذف الغرف عند إعادة التشغيل. تأكد من سياسة Render الحالية قبل الاعتماد عليها.
